# 叫不出名字的东西

> **Unknown Unknowns** · 独立开发者的扫盲词典。不是知识库，不是教程。

**在线版 → [elysianx138.github.io/unknown-unknowns](https://elysianx138.github.io/unknown-unknowns/)**（能搜、能标"没听过 / 说不清 / 会了"，标注存在你本地浏览器）

**你不知道一个词，就不会去搜它；不搜它，AI 也帮不了你 —— 因为 AI 只回答你问得出的问题。**

这个仓库只做一件事：把人从「不知道有这回事」推到「知道它叫 X」。深度不管，原理不讲，结论不给。

**扫盲 ≠ 学会。** 知道一个词存在、知道它在哪儿咬你、知道该搜什么，不等于会做。这一行不放在最前面，它就会长成一本没人读完的教材。

---

## 六个字段怎么读

- **是什么** —— 它管什么。两句话，不解释原理。
- **什么时候会遇到** —— 你人生里第一次撞见它的场景（不是"重要性"，是"什么时候"）。
- **不知道会怎样** —— 具体后果。写"会有风险"的都不算。
- **怎么查** —— 搜什么词，外加一个能点的一手资料。
- **关联** —— 会和你一起出现、连起来才咬人的词。单个词是词汇，两个词之间才是坑。

## 为什么是「词」，不是「知识」

- 内容本身没有价值。任何模型被问一句「独立开发者出海要注意什么」，都能给出比这里更全的答案。所以这里不解释、不论证、不复制文档。
- 唯一稀缺的是取舍：一个人、没钱、做 Web 游戏、面向海外 —— 哪 65 个词真的会咬到他，按什么顺序咬。
- **扫盲有终点。** 一个领域 60–80 个词就覆盖了大部分「第一次撞墙」。扫完就是扫完了，不用维护一个五年黑洞。

## 怎么用

1. 从头读一遍，拿笔划三类：**① 完全没听过 ② 听过但说不清它在管什么 ③ 已经会的**。
2. ① 超过 20 个 → 这份表对你有用；③ 超过一半 → 这一层你扫完了，该往下钻（比如「游戏出海」再扫一层）。
3. **别一个个拿去「详细问」AI。** 每个词只要三样东西：它管什么、什么时候会遇到、怎么查。深度只留给你下周真要做的那一个。否则会问 65 个问题、读 65 段两千字回答，一个都不记得。

## 1｜第一次把它放到公网

### DNS / A 记录 / CNAME
- **是什么**：域名到 IP 的那层"电话簿"。A 记录直接写 IP；CNAME 指向另一个域名，用来把子域交给 CDN 或平台托管。改完不是立刻生效，要等 TTL。
- **什么时候会遇到**：换服务器、绑自定义域名、接 CDN、把域名从一家注册商挪到另一家。
- **不知道会怎样**：白屏或还跳旧地址，你先怀疑代码，查两天才发现解析还指着早就下线的那台机器。
- **怎么查**：搜 `DNS A记录 CNAME 区别` · [Cloudflare: 什么是 DNS](https://www.cloudflare.com/learning/dns/what-is-dns/)
- **关联**：TTL、CDN 强缓存、HTTPS 证书链

### TTL
- **是什么**：一条解析结果在别人机器上缓存多久（秒）。它不是"生效时间"，是"最坏情况下多久之后，所有人都会看到新值"。
- **什么时候会遇到**：切服务器、切 CDN、换域名的那一天。
- **不知道会怎样**：反复改来改去，一半用户看到新的、一半看到旧的，你以为是自己又改错了。
- **怎么查**：搜 `DNS TTL 设置多少合适` · [Cloudflare: TTL](https://www.cloudflare.com/learning/cdn/glossary/time-to-live-ttl/)
- **关联**：DNS / A 记录 / CNAME、CDN 强缓存

### HTTPS / 证书链
- **是什么**：TLS 加密，加上一张由 CA 签发的证书，再加上把"中间证书"也一并发给浏览器的那条链。链断了，浏览器就不知道该信谁给你担保。
- **什么时候会遇到**：上线第一天、证书 90 天到期、换服务器忘了迁证书。
- **不知道会怎样**：浏览器标"不安全"或整个站打不开，你以为是后端挂了。
- **怎么查**：搜 `证书链不完整 表现` · [MDN: HTTPS](https://developer.mozilla.org/en-US/docs/Glossary/HTTPS)
- **关联**：DNS / A 记录 / CNAME、CDN 强缓存

### CORS / 同源策略
- **是什么**：浏览器规定"A 域的页面不能随便读 B 域的响应"，除非 B 在响应头里显式允许。注意：拦的是浏览器里的**读取**，请求其实已经发出去了——所以后端日志有记录，前端却拿到报错。
- **什么时候会遇到**：前后端分域部署、前端直连第三方 API、加了自定义请求头。
- **不知道会怎样**：本地全通，上线全 403，你查一天后端，最后发现少一个 `Access-Control-Allow-Origin`。
- **怎么查**：搜 `CORS 预检请求 报错` · [MDN: CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS)
- **关联**：环境变量 / .env、CDN 强缓存

### 环境变量 / .env
- **是什么**：把配置（数据库地址、API key、开关）从代码里拿出来，按环境注入。`.env` 只是本地开发用的文件，不该进仓库。
- **什么时候会遇到**：第一次连数据库、第一次放第三方 key、第一次部署到服务器。
- **不知道会怎样**：数据库密码跟着 git 历史永久公开，删掉文件也没用，历史里还在。
- **怎么查**：搜 `.env 不该提交 git` · [12-Factor: Config](https://12factor.net/config)
- **关联**：密钥泄露 / secret scanning、成本告警 / 预算上限

### CDN / 强缓存
- **是什么**：把静态文件复制到离用户近的节点，并用 `Cache-Control` 告诉浏览器"这个文件能存多久"。文件名里带 hash，才敢设长缓存。
- **什么时候会遇到**：改了前端但用户说没变化；或者首页 HTML 被缓存，用户一直看到旧版本。
- **不知道会怎样**：你在自己电脑上刷新一百遍都是新的，用户那边永远是旧的，而你找不到原因。
- **怎么查**：搜 `Cache-Control 强缓存 刷新` · [MDN: Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Cache-Control)
- **关联**：TTL、HTTPS 证书链

### ICP 备案
- **是什么**：在中国大陆用域名 + 境内服务器对外提供网站，要先在工信部系统登记主体和域名。海外托管不适用，但哪天把服务器放回国内就要。
- **什么时候会遇到**：想面向国内用户，或者想接国内的支付 / 广告 / 平台。
- **不知道会怎样**：站点被直接拦截，补办要几周，期间什么都做不了。
- **怎么查**：搜 `ICP 备案 流程 时间` · [工信部备案系统](https://beian.miit.gov.cn/)
- **关联**：分发渠道、内容分级 / IARC

## 2｜第一次想让陌生人发现它

### SEO / 收录 / sitemap
- **是什么**：让搜索引擎发现、抓取、索引你的页面，并在有人搜相关词时把你排上去。这是三件事：能被发现（链接、sitemap）、允许抓（robots）、值得排（内容与标题）。
- **什么时候会遇到**：想让陌生人搜到你，而不是只靠你自己发链接。
- **不知道会怎样**：你优化了三个月关键词，站点其实压根没被收录——搜 `site:你的域名` 一条都没有。
- **怎么查**：搜 `新站 SEO 收录周期` · [Google 搜索入门指南](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)
- **关联**：Meta tag 家族、Landing page / CTA、UTM

### Meta tag 家族（含 OG / Twitter Card）
- **是什么**：`<head>` 里给机器看的那堆标签：`title`/`description` 给搜索引擎，`og:*` 给社交平台的链接预览（标题、图、描述），`twitter:*` 是同一件事的另一套写法。OG 只是其中一组。
- **什么时候会遇到**：把链接发到 Discord / X / 微信 / Slack，或者发现搜索结果里的摘要不对。
- **不知道会怎样**：分享出去是一块白板或一行光秃秃的 URL，没人点。
- **怎么查**：搜 `og:image 尺寸 预览` · [The Open Graph protocol](https://ogp.me/)
- **关联**：SEO / 收录 / sitemap、Landing page / CTA、UTM

### Landing page / CTA
- **是什么**：一个只为"让来的人做一件事"而存在的页面；CTA 就是那件事的按钮或链接（开始玩、留邮箱、买）。页面上每个元素要么推动它，要么删掉。
- **什么时候会遇到**：第一次做介绍页、第一次投放、第一次从别人的流量里接人。
- **不知道会怎样**：人来了，看完不知道下一步点哪，直接关掉，你还以为是自己不够好看。
- **怎么查**：搜 `landing page 结构 转化` · [Wikipedia: Call to Action](https://en.wikipedia.org/wiki/Call_to_action_%28marketing%29)
- **关联**：埋点 / 事件、漏斗、SEO / 收录 / sitemap

### 冷启动 / 前 100 个用户
- **是什么**：从 0 到 1 的那批用户。它几乎不可能来自"上线后自然增长"，只能来自你一个一个去拉。
- **什么时候会遇到**：东西能用了，但一个人都没有。
- **不知道会怎样**：等"自然流量"，等三个月，然后放弃。
- **怎么查**：搜 `indie game first 100 players` · [PG: Do Things That Don't Scale](https://paulgraham.com/ds.html)
- **关联**：分发渠道、邮件列表 / newsletter、会话录屏 / 热图

### 分发渠道
- **是什么**：Poki、CrazyGames、itch.io、Newgrounds、Reddit、Discord 各是一套规则和一种流量：策展制平台看质量与完整度，社区看你是不是来发广告的。
- **什么时候会遇到**：第一次提交游戏、第一次发帖。
- **不知道会怎样**：只发一个地方，或者发错版块被删，然后得出"没人喜欢我的游戏"的结论。
- **怎么查**：搜 `Web 游戏 发行渠道 对比` · [CrazyGames 开发者文档](https://developer.crazygames.com/)
- **关联**：分成比例、独家 / 首发条款、UTM

### 邮件列表 / newsletter
- **是什么**：用户主动给你的订阅关系，是唯一不经过平台算法的触达渠道。平台改规则、限流、封号时，它是你唯一剩下的东西。
- **什么时候会遇到**：想让用户"下次还找得到你"，或者平台改规则之后。
- **不知道会怎样**：用户全在平台手里，规则一改你就归零，连通知都没地方发。
- **怎么查**：搜 `newsletter 工具 免费额度` · [Mailchimp: 邮件营销基础](https://mailchimp.com/resources/)
- **关联**：冷启动 / 前 100 个用户、GDPR、Cookie 同意 / consent

### UTM
- **是什么**：URL 后面那串 `?utm_source=…&utm_medium=…`，告诉分析工具"这个人是被哪个渠道、哪次投放带进来的"。
- **什么时候会遇到**：同一天在几个地方发了同一个链接。
- **不知道会怎样**：你知道有人来、有人转化，但不知道是哪条渠道带来的，推广全靠猜。
- **怎么查**：搜 `utm_source utm_medium 规范` · [Google Analytics: UTM 参数](https://support.google.com/analytics/answer/1033863)
- **关联**：埋点 / 事件、漏斗、分发渠道

## 3｜第一个陌生用户来了

### 埋点 / 事件
- **是什么**：在关键动作上打点（打开、开始、过关、付费），把"用户做了什么"变成可查的记录。它和日志不是一回事：日志记错误，埋点记行为。
- **什么时候会遇到**：上线第一天，或者"我感觉有人在用但不确定"。
- **不知道会怎样**：你只有"来过多少人"，没有"在哪一步走掉"，于是只能猜。
- **怎么查**：搜 `最小埋点方案` · [GA4: 事件](https://developers.google.com/analytics/devguides/collection/ga4/events)
- **关联**：漏斗、UTM、Cookie 同意 / consent

### 漏斗
- **是什么**：把一串事件按顺序排成"进入 → 第 2 步 → 第 3 步 → 完成"，看每一步剩下多少人。
- **什么时候会遇到**：有人来，但没人用成。
- **不知道会怎样**：你以为转化低是定价问题，其实第 2 步就崩了 60%。
- **怎么查**：搜 `漏斗分析 怎么设` · [Amplitude: 漏斗分析](https://amplitude.com/blog/funnel-analysis)
- **关联**：埋点 / 事件、Landing page / CTA、A/B 测试

### 留存 / 留存曲线
- **是什么**：第一天来的那批人，第 2 天、第 7 天、第 30 天还剩多少。曲线最后若趋近于 0，说明产品没有一个"回来的理由"。
- **什么时候会遇到**：第一次看数据，或者想判断"这东西到底有没有人喜欢"。
- **不知道会怎样**：把"来过"当"喜欢"，日活好看，但产品在漏。
- **怎么查**：搜 `留存曲线 怎么读` · [搜一下](https://www.bing.com/search?q=%E7%95%99%E5%AD%98%E6%9B%B2%E7%BA%BF+%E6%80%8E%E4%B9%88%E8%AF%BB)
- **关联**：DAU / MAU / 粘性、漏斗、订阅 / 买断 / 内购

### DAU / MAU / 粘性
- **是什么**：日活、月活，以及它们的比值（DAU/MAU，常被叫粘性）。同一个"活跃"，三个团队可以有三种定义。
- **什么时候会遇到**：跟别人对数据、算增长、写发行材料。
- **不知道会怎样**：三个数各说各话，你也不知道该信哪个，更没法判断涨的是真还是假。
- **怎么查**：搜 `DAU MAU 定义 区别` · [搜一下](https://www.bing.com/search?q=DAU+MAU+%E5%AE%9A%E4%B9%89+%E5%8C%BA%E5%88%AB)
- **关联**：留存 / 留存曲线、埋点 / 事件

### A/B 测试
- **是什么**：同一时间把流量随机分成两组，只改一个变量，比较结果。关键是"只改一个"，否则你永远不知道是哪个起作用。
- **什么时候会遇到**：想改文案、定价、按钮，但不确定会不会更差。
- **不知道会怎样**：改完凭感觉来回改，永远不知道是变好还是变坏，最后回到原样。
- **怎么查**：搜 `A/B 测试 最小样本量` · [Optimizely: A/B 测试](https://www.optimizely.com/optimization-glossary/ab-testing/)
- **关联**：漏斗、Landing page / CTA、留存 / 留存曲线

### 会话录屏 / 热图
- **是什么**：录屏按时间回放真实用户的操作，热图把点击和滚动聚成密度图。它们回答"人到底点了哪"，而不是"人有多少"。
- **什么时候会遇到**：猜不透用户为什么不按你想的走。
- **不知道会怎样**：你以为最明显的按钮，其实没人看见——因为它在首屏之外。
- **怎么查**：搜 `session replay 工具 免费` · [Microsoft Clarity](https://learn.microsoft.com/en-us/clarity/)
- **关联**：GDPR、COPPA、埋点 / 事件

## 4｜第一次收钱

### Merchant of Record（MoR）
- **是什么**：法律上"卖给用户的是这家公司"的那一方，它替你收钱、算税、开票、处理退款和拒付。Paddle、Lemon Squeezy 是这类；Stripe 不是——Stripe 只是支付处理商，税还是你自己的事。
- **什么时候会遇到**：想卖数字产品给全球个人用户，又不想自己注册每个国家的税号。
- **不知道会怎样**：以为接了 Stripe 就完事，结果 VAT/GST 的注册和申报全落在你头上。
- **怎么查**：搜 `Merchant of Record 是什么` · [Paddle: What is a MoR](https://www.paddle.com/blog/what-is-a-merchant-of-record)
- **关联**：支付通道 / 商户主体、VAT / GST、退款政策

### 支付通道 / 商户主体
- **是什么**：付钱按钮背后得有一个能收款的账户。Stripe 需要可用的商户主体（地区、身份、业务类型都会影响能否开户），Paddle / PayPal 是另一套门槛。
- **什么时候会遇到**：放第一个付费按钮**之前**，不是之后。
- **不知道会怎样**：按钮和页面都做完了，才发现自己开不了户，或者开户要等两周审核。
- **怎么查**：搜 `Stripe 中国大陆 个人 支持` · [Stripe 文档](https://docs.stripe.com/get-started)
- **关联**：Merchant of Record（MoR）、风控 / 冻结、W-8BEN

### 风控 / 冻结
- **是什么**：支付平台对你账户的风险评分。进账突然变多、地区异常、拒付率高都会触发；触发后常见动作是冻结余额、暂停提现。
- **什么时候会遇到**：第一波真实收入进来的时候——也正是你最需要钱的时候。
- **不知道会怎样**：钱卡在里面几十天到 180 天，你以为是系统 bug，其实是被风控了。
- **怎么查**：搜 `Stripe 风控 冻结 原因` · [Stripe Radar](https://docs.stripe.com/radar)
- **关联**：Chargeback（拒付）、争议率 / 阈值、Merchant of Record（MoR）

### 3DS / SCA
- **是什么**：欧洲的强客户认证要求：付款时多一步银行验证（3DS2）。很多卡如果不走这一步就直接失败。
- **什么时候会遇到**：欧洲用户付款失败率异常高的时候。
- **不知道会怎样**：你去改定价、改文案、改按钮，其实是认证根本没通过。
- **怎么查**：搜 `3DS2 SCA 支付失败` · [Stripe: 3D Secure](https://docs.stripe.com/payments/3d-secure)
- **关联**：支付通道 / 商户主体、Merchant of Record（MoR）

### 订阅 / 买断 / 内购
- **是什么**：三种计费结构：一次性买断、周期订阅（自动续费 + 失败重试 + 退订）、平台内购（平台抽成 + 平台管账）。它决定了你的账单系统长什么样。
- **什么时候会遇到**：定价之前，或者第一次想加"付费"功能。
- **不知道会怎样**：先做买断，后来改订阅，账单逻辑要重写，老用户还要迁移。
- **怎么查**：搜 `订阅 vs 买断 定价` · [Stripe Billing](https://docs.stripe.com/billing)
- **关联**：定价锚点 / 分层定价、留存 / 留存曲线、Freemium / 试用

### 定价锚点 / 分层定价
- **是什么**：把价格摆成几档，让中间那档显得"划算"。用户比的不是绝对值，是相邻两个价签之间的差。
- **什么时候会遇到**：第一次给自己的东西定价。
- **不知道会怎样**：只有一个价，用户要么买要么走，你没有中间地带可以接住犹豫的人。
- **怎么查**：搜 `定价 分层 锚点` · [搜一下](https://www.bing.com/search?q=%E5%AE%9A%E4%BB%B7+%E5%88%86%E5%B1%82+%E9%94%9A%E7%82%B9)
- **关联**：订阅 / 买断 / 内购、Freemium / 试用

### Freemium / 试用
- **是什么**：免费额度或限时试用，让用户先体验到价值再付费。给多给少是产品设计，不是营销话术。
- **什么时候会遇到**：想降低第一次尝试的门槛。
- **不知道会怎样**：给太多没人付，给太少没人留，而且你分不清是哪一种。
- **怎么查**：搜 `free trial vs freemium` · [搜一下](https://www.bing.com/search?q=free+trial+vs+freemium)
- **关联**：定价锚点 / 分层定价、留存 / 留存曲线、订阅 / 买断 / 内购

## 5｜第一次要放合规文本

### GDPR
- **是什么**：欧盟的数据保护条例，管的是"处理欧盟境内个人数据"，不管公司注册在哪。个人数据包括邮箱、IP、Cookie 标识、录屏里的画面。
- **什么时候会遇到**：只要有欧盟用户，并且你收集或处理了任何能关联到人的信息。
- **不知道会怎样**：被投诉时你拿不出任何告知与授权记录，连"我尽力了"都证明不了。
- **怎么查**：搜 `GDPR 域外适用 个人开发者` · [GDPR 全文](https://gdpr-info.eu/)
- **关联**：Cookie 同意 / consent、隐私政策 / 服务条款 / EULA、删除权 / 数据保留期

### CCPA / CPRA
- **是什么**：加州版的隐私法，核心是"用户有权知道、删除、拒绝出售个人信息"。它有适用门槛（营收/用户量），但被投诉时先看的还是你有没有告知。
- **什么时候会遇到**：有加州用户，尤其是你在美国做增长的时候。
- **不知道会怎样**：以为"我只做欧洲"，美国这边同样有义务，而且是按人头罚。
- **怎么查**：搜 `CCPA 适用门槛` · [加州总检察长: CCPA](https://oag.ca.gov/privacy/ccpa)
- **关联**：GDPR、隐私政策 / 服务条款 / EULA、Cookie 同意 / consent

### Cookie 同意 / consent
- **是什么**：非必要的 Cookie（分析、广告）要先拿到用户同意，并且要能撤回。同意之前不能先写。
- **什么时候会遇到**：装分析工具或广告 SDK 的那一天。
- **不知道会怎样**：欧盟算违规，而且你没法证明"我告知过"——因为弹窗是后来才加上去的。
- **怎么查**：搜 `Cookie banner 合规` · [ICO: Cookies 指引](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guide-to-pecr/cookies-and-similar-technologies/)
- **关联**：GDPR、埋点 / 事件、广告 SDK / 激励视频

### COPPA
- **是什么**：美国管 13 岁以下儿童数据的法。游戏天然吸引小孩，所以这条最容易踩；它要求可验证的家长同意，而不是一句"未满 13 岁请勿使用"。
- **什么时候会遇到**：游戏上线、接广告联盟、填平台的分级问卷。
- **不知道会怎样**：平台先罚，再回头找你；广告 SDK 也会因为这条直接封号。
- **怎么查**：搜 `COPPA 游戏 合规` · [FTC: COPPA](https://www.ecfr.gov/current/title-16/chapter-I/subchapter-C/part-312)
- **关联**：内容分级 / IARC、会话录屏 / 热图、广告 SDK / 激励视频

### 隐私政策 / 服务条款 / EULA
- **是什么**：三份不同的东西：隐私政策（我怎么处理你的数据）、服务条款（你我能做什么、出了事怎么办）、EULA（软件许可，游戏常要）。一份"用户协议"覆盖不了三件事。
- **什么时候会遇到**：上线前，以及申请支付通道 / 上架平台时（它们会要链接）。
- **不知道会怎样**：平台直接拒审；或者被投诉时，你写的条款根本管不到那件事。
- **怎么查**：搜 `隐私政策 必备条款` · [GDPR 第 13 条：告知义务](https://gdpr-info.eu/art-13-gdpr/)
- **关联**：GDPR、CCPA / CPRA、平台审核（技术规范）

### DPA（数据处理协议）
- **是什么**：你和支付、分析、云服务商之间划分"谁是控制者、谁是处理者"的合同。大多数 SaaS 的 DPA 是现成的，你要做的是接受并留档。
- **什么时候会遇到**：接第三方 SDK、支付、邮件服务时。
- **不知道会怎样**：出事时说不清数据是谁的责任：你说"是他们的"，对方说"是你配的"。
- **怎么查**：搜 `DPA 数据控制者 处理者` · [GDPR 第 28 条](https://gdpr-info.eu/art-28-gdpr/)
- **关联**：GDPR、Merchant of Record（MoR）、Cookie 同意 / consent

### 删除权 / 数据保留期
- **是什么**：用户有权要求删除他的数据，你也有义务"不留超过必要期限"。难的不是删主库，是备份、日志、和第三方手里的副本。
- **什么时候会遇到**：第一个"请删除我的账号"的邮件。
- **不知道会怎样**：现找现删，主库删了备份里还有，回答时也没法说"已彻底删除"。
- **怎么查**：搜 `right to erasure 实操` · [GDPR 第 17 条](https://gdpr-info.eu/art-17-gdpr/)
- **关联**：GDPR、备份 / 回滚

## 6｜第一次被平台审核

### 分成比例（revenue share）
- **是什么**：平台从你的收入里抽多少，以及抽的是"流水"还是"净收入"。同样写 30%，算法不同差很多。
- **什么时候会遇到**：算收入模型、比较渠道的时候。
- **不知道会怎样**：算完成本才发现到手只剩三成，你的定价从一开始就是错的。
- **怎么查**：搜 `Poki CrazyGames 分成` · [CrazyGames 开发者文档](https://developer.crazygames.com/)
- **关联**：分发渠道、定价锚点 / 分层定价、广告 SDK / 激励视频

### 独家 / 首发条款
- **是什么**：平台要求你的游戏在它那里独家、或者首发一段时间，用来换推荐位或更高分成。
- **什么时候会遇到**：签第一份平台协议。
- **不知道会怎样**：签完才发现上不了别的平台，而那个平台本来是你的主要流量。
- **怎么查**：搜 `游戏发行 独家 条款` · [搜一下](https://www.bing.com/search?q=%E6%B8%B8%E6%88%8F%E5%8F%91%E8%A1%8C+%E7%8B%AC%E5%AE%B6+%E6%9D%A1%E6%AC%BE)
- **关联**：分发渠道、分成比例（revenue share）

### 技术规范
- **是什么**：平台对包体大小、加载时长、SDK 接入、广告调用时机、移动端适配的一堆硬性要求。它们不在创意指南里，在提交文档里。
- **什么时候会遇到**：第一次提交。
- **不知道会怎样**：被拒，而且不知道原因；重投一次又是两周。
- **怎么查**：搜 `CrazyGames 提交要求` · [CrazyGames 文档](https://developer.crazygames.com/)
- **关联**：广告 SDK / 激励视频、审核周期 / 申诉、内容分级 / IARC

### 内容分级 / IARC
- **是什么**：国际年龄分级联盟的问卷，平台用它给你的游戏定年龄标签。问卷答的是"游戏里有什么"，不是"你希望它是什么级别"。
- **什么时候会遇到**：提交时必填；接广告时也会被要求。
- **不知道会怎样**：填错分级，平台直接下架，广告主也会拉黑。
- **怎么查**：搜 `IARC 问卷 怎么填` · [IARC](https://www.globalratings.com/)
- **关联**：COPPA、广告 SDK / 激励视频、技术规范

### 广告 SDK / 激励视频
- **是什么**：Web 游戏的 IAA 收入主要来自激励视频（用户主动看完换奖励）和插屏。SDK 决定你拿多少、什么时候能调。
- **什么时候会遇到**：想靠广告而不是付费赚钱。
- **不知道会怎样**：接错 SDK 或调用时机不对，收入归平台不归你，或者直接违反规范被下架。
- **怎么查**：搜 `激励视频 eCPM` · [Poki SDK](https://sdk.poki.com/)
- **关联**：分成比例（revenue share）、技术规范、Cookie 同意 / consent

### 审核周期 / 申诉
- **是什么**：提交之后的排队、人工审核，以及被拒后唯一的沟通渠道（通常是邮件或后台工单）。周期从几小时到几周不等。
- **什么时候会遇到**：第一次提交，或者改版后重新提交。
- **不知道会怎样**：卡在审核里两周，你没有任何入口问"到底哪里不行"。
- **怎么查**：搜 `平台 审核 申诉 邮件` · [CrazyGames 开发者文档](https://developer.crazygames.com/)
- **关联**：技术规范、分发渠道

## 7｜第一次退款、差评、投诉

### Chargeback（拒付）
- **是什么**：用户不找你，直接找发卡行说"这笔不是我授权的 / 我没收到货"，银行先把钱划回去，再由你举证。
- **什么时候会遇到**：第一个不满的付费用户，或者被盗刷的卡。
- **不知道会怎样**：不理它 → 罚手续费 + 拒付率上升 → 通道被关，钱和生意一起停。
- **怎么查**：搜 `chargeback 流程 商户责任` · [Stripe: 争议处理](https://docs.stripe.com/disputes)
- **关联**：争议率 / 阈值、风控 / 冻结、退款政策

### 争议率 / 阈值
- **是什么**：拒付笔数（或金额）占你总交易的比例。卡组织有红线（常见在 1% 上下，具体看通道），超了会被列入监控名单。
- **什么时候会遇到**：收到第一封争议通知。
- **不知道会怎样**：你以为是单个用户的事，其实是账户生死——通道会在某天直接停掉你。
- **怎么查**：搜 `Stripe 争议率 阈值` · [Stripe: 争议](https://docs.stripe.com/disputes)
- **关联**：Chargeback（拒付）、风控 / 冻结

### 退款政策
- **是什么**：写明什么情况退、退多少、多久内、走什么流程。它既是对用户的承诺，也是对抗拒付的第一道证据。
- **什么时候会遇到**：上架或开户时会被要求提供；第一个用户要求退款时。
- **不知道会怎样**：每个用户单独谈，越谈越亏，而且没有一致性——下一个人会拿上一个人的条件来谈。
- **怎么查**：搜 `数字产品 退款政策 怎么写` · [搜一下](https://www.bing.com/search?q=%E6%95%B0%E5%AD%97%E4%BA%A7%E5%93%81+%E9%80%80%E6%AC%BE%E6%94%BF%E7%AD%96)
- **关联**：Chargeback（拒付）、隐私政策 / 服务条款 / EULA、SLA / 响应时限

### SLA / 响应时限
- **是什么**：你承诺多久内回应、多久内修复。对独立开发者，它真正的价值不是写给客户看，而是给自己一条"多久必须回"的硬线。
- **什么时候会遇到**：第一个工单、第一次线上事故。
- **不知道会怎样**：48 小时没回，投诉升级成公开差评，而你还在写代码。
- **怎么查**：搜 `SLA 定义 示例` · [搜一下](https://www.bing.com/search?q=SLA+%E5%AE%9A%E4%B9%89+%E7%A4%BA%E4%BE%8B)
- **关联**：工单 / 客服邮箱、差评处理 / 舆情

### 工单 / 客服邮箱
- **是什么**：一个固定的收件入口，加一个能追踪状态的系统（哪怕只是邮箱标签）。关键是别让投诉掉进你的私人邮箱和垃圾邮件。
- **什么时候会遇到**：用户第一次想联系你。
- **不知道会怎样**：投诉发到你私人邮箱，混在垃圾邮件里，两周后你才发现。
- **怎么查**：搜 `客服 工单 工具 免费` · [搜一下](https://www.bing.com/search?q=%E5%AE%A2%E6%9C%8D+%E5%B7%A5%E5%8D%95+%E5%B7%A5%E5%85%B7+%E5%85%8D%E8%B4%B9)
- **关联**：SLA / 响应时限、退款政策

### 差评处理 / 舆情
- **是什么**：公开平台上的负面评价会被算法放大，你回复的方式决定它是"一个用户"还是"一群人"。
- **什么时候会遇到**：第一条差评、第一条吐槽帖。
- **不知道会怎样**：情绪化回复，把一个人变成一群人，而且截图会一直跟着你。
- **怎么查**：搜 `差评 回复 模板` · [搜一下](https://www.bing.com/search?q=%E5%B7%AE%E8%AF%84+%E5%9B%9E%E5%A4%8D+%E6%A8%A1%E6%9D%BF)
- **关联**：SLA / 响应时限、分发渠道、工单 / 客服邮箱

## 8｜第一次被抄

### 著作权（自动取得）vs 登记
- **是什么**：作品完成即自动拥有版权，不需要注册。登记的作用是**举证方便**：发生纠纷时，你手里有一张官方日期。
- **什么时候会遇到**：发现有人原样搬运你的代码、美术、文案。
- **不知道会怎样**：你以为"我做的当然是我的"，但拿不出时间证据和授权记录，投诉无门。
- **怎么查**：搜 `著作权 自动取得 与 登记 区别` · [US Copyright Office](https://www.copyright.gov/what-is-copyright/)
- **关联**：证据链 / 时间戳、DMCA takedown、商标

### 商标
- **是什么**：名字和 logo 的独占权，必须注册才强。商标按类别注册：你在"游戏软件"注册，不代表在"服饰"也归你。
- **什么时候会遇到**：起名、发第一版、发现别人用了相似的名字。
- **不知道会怎样**：被人在别处注册，你反而不能用自己用了两年的名字。
- **怎么查**：搜 `商标 注册 类别 费用` · [USPTO: 商标基础](https://www.uspto.gov/trademarks/basics)
- **关联**：著作权（自动取得）vs 登记、DMCA takedown

### 开源许可证
- **是什么**：MIT / Apache 基本随便用；GPL 要求衍生作品也开源；AGPL 连"通过网络提供服务"也算分发。引一个库之前，先看它的 LICENSE 文件。
- **什么时候会遇到**：引别人的代码或库、把自己的项目开源。
- **不知道会怎样**：引了 GPL 的代码，你的整个项目被迫开源，或者被要求下架。
- **怎么查**：搜 `MIT GPL AGPL 商用 区别` · [Choose a License](https://choosealicense.com/)
- **关联**：依赖投毒 / 供应链、素材授权

### DMCA takedown
- **是什么**：美国那套"通知—删除"流程：你向平台发正式通知，平台下架，对方可以反通知。它是流程，不是"发帖骂人"。
- **什么时候会遇到**：别人抄了你的站、素材、代码，并挂在某个平台上。
- **不知道会怎样**：只会发帖骂，没有实际动作，抄袭者继续挂着。
- **怎么查**：搜 `DMCA takedown 流程` · [GitHub: DMCA 政策](https://docs.github.com/en/site-policy/content-removal-policies/dmca-takedown-policy)
- **关联**：著作权（自动取得）vs 登记、证据链 / 时间戳

### 证据链 / 时间戳
- **是什么**：能证明"我在某个时间点就已经有这个东西"的材料：提交记录、带时间的公开发布、第三方存证。
- **什么时候会遇到**：要投诉、要维权、要和平台对质的时候。
- **不知道会怎样**：你有一百个"我记得"，但没有一条能拿出来的记录。
- **怎么查**：搜 `时间戳 存证 方式` · [搜一下](https://www.bing.com/search?q=%E6%97%B6%E9%97%B4%E6%88%B3+%E5%AD%98%E8%AF%81)
- **关联**：著作权（自动取得）vs 登记、DMCA takedown

### 素材授权
- **是什么**：字体、音乐、图标、AI 生成图的商用条款各不相同：有的免费但要署名，有的只许个人用，有的按坐席收费。
- **什么时候会遇到**：第一次用"免费素材"，或者上线后收到授权方的信。
- **不知道会怎样**：用了商业字体，被追讨授权费——按使用量算，可能比整个项目赚的都多。
- **怎么查**：搜 `字体 商用 授权` · [Google Fonts: 许可说明](https://developers.google.com/fonts/faq)
- **关联**：开源许可证、著作权（自动取得）vs 登记

## 9｜第一次算税

### W-8BEN
- **是什么**：非美国个人向美国公司（含平台）声明"我不是美国纳税人"的表，用来确定预扣税率。没填或填错，默认按最高税率扣。
- **什么时候会遇到**：第一次从美国平台（Apple、Google、Steam、Stripe 等）拿钱。
- **不知道会怎样**：被按 30% 预扣，差额是真金白银，而且事后追回很麻烦。
- **怎么查**：搜 `W-8BEN 怎么填` · [IRS: Form W-8BEN](https://www.irs.gov/forms-pubs/about-form-w-8-ben)
- **关联**：预扣税 / 税收协定、Merchant of Record（MoR）

### 预扣税 / 税收协定
- **是什么**：美国对非居民的某些收入（如特许权使用费）默认预扣 30%，中美税收协定下这部分可降到 10%——前提是你填了 W-8BEN 并声明协定待遇。
- **什么时候会遇到**：填完表、收到第一笔款、对账时发现少了三成。
- **不知道会怎样**：能按 10% 的，你交了 30%；或者以为平台"收了税"，其实那只是预扣，年底还要自己处理。
- **怎么查**：搜 `中美税收协定 特许权使用费 预扣` · [IRS: 税收协定](https://www.irs.gov/businesses/international-businesses/united-states-income-tax-treaties-a-to-z)
- **关联**：W-8BEN、代扣代缴 / 税收抵免、个人所得税 / 经营所得

### VAT / GST
- **是什么**：欧盟、英国、澳洲等对数字服务征收的消费税，按用户所在地税率算。MoR 会替你处理；自己直连收款的，得自己去注册 OSS 之类的申报机制。
- **什么时候会遇到**：卖数字产品给这些地区的个人用户。
- **不知道会怎样**：MoR 替你处理了，但你不知道它处理了；换成直连支付后，你以为价格就是收入，其实还欠一笔税。
- **怎么查**：搜 `digital services VAT MoR` · [EU: OSS](https://vat-one-stop-shop.ec.europa.eu/)
- **关联**：Merchant of Record（MoR）、定价锚点 / 分层定价、W-8BEN

### 个人所得税 / 经营所得
- **是什么**：国内这头，境外收入要按"劳务 / 经营 / 特许权"等不同口径申报。平台代扣的，和你自己要申报的，不是同一件事。
- **什么时候会遇到**：第一笔海外收入到账、第一次年度汇算。
- **不知道会怎样**：两头都没报；或者以为平台扣过了就完事，实际那只是预扣。
- **怎么查**：搜 `境外收入 个税 申报 实操` · [国家税务总局](https://www.chinatax.gov.cn/)
- **关联**：预扣税 / 税收协定、代扣代缴 / 税收抵免、发票 / 收据

### 代扣代缴 / 税收抵免
- **是什么**：平台在付款时代扣的税，通常会给你凭证；这部分在境内申报时可能可以抵免，避免同一笔钱交两次。
- **什么时候会遇到**：报税那年，尤其是海外收入开始有几万块的时候。
- **不知道会怎样**：同一笔钱交两次；或者拿不出代扣凭证，抵不了。
- **怎么查**：搜 `境外已缴税 抵免` · [国家税务总局](https://www.chinatax.gov.cn/)
- **关联**：预扣税 / 税收协定、个人所得税 / 经营所得

### 发票 / 收据
- **是什么**：给企业客户开票的能力（国内是增值税发票，海外是 invoice / receipt）。平台给你的结算单不是发票。
- **什么时候会遇到**：接到第一个 B 端单，或者客户要求报销。
- **不知道会怎样**：开不出票，单子黄了；或者拿平台的结算单当发票，对方财务不认。
- **怎么查**：搜 `个人 代开发票 流程` · [电子税务局](https://inv-veri.chinatax.gov.cn/)
- **关联**：个人所得税 / 经营所得、Merchant of Record（MoR）

## 10｜第一次被搞 / 账单爆炸

### 密钥泄露 / secret scanning
- **是什么**：把 API key、数据库密码写进代码并推到公开仓库。GitHub 会扫描已知格式的密钥并告警，但私有库和历史提交它不一定救得了你。
- **什么时候会遇到**：仓库变 public 的那一刻起，以及每一次 `git add .` 之前。
- **不知道会怎样**：key 在几分钟内被爬走，跑掉几百万 token 或几千块云资源——账单在你睡着的时候产生。
- **怎么查**：搜 `GitHub secret scanning 泄露 key 处理` · [GitHub: Secret scanning](https://docs.github.com/en/code-security/secret-scanning/introduction/about-secret-scanning)
- **关联**：环境变量 / .env、成本告警 / 预算上限

### 依赖投毒 / 供应链
- **是什么**：npm / PyPI 上的包可能被作者或攻击者塞进恶意代码（安装脚本、挖矿、偷读环境变量）。你 `npm i` 的那一刻，它已经在你的构建里跑过了。
- **什么时候会遇到**：随手装了个没听过的小包，或者一个用了很久的包突然发了新版。
- **不知道会怎样**：你什么都没改，代码里多了一段挖矿，或者 CI 里的密钥被读走。
- **怎么查**：搜 `npm 供应链攻击 检测` · [npm 文档](https://docs.npmjs.com/)
- **关联**：开源许可证、密钥泄露 / secret scanning

### 限流 / 防刷 / 验证码
- **是什么**：对每个 IP / 账号 / 接口设速率上限，超了就拒。没有它，任何能匿名调用的接口都等于一份公开的免费额度。
- **什么时候会遇到**：接口能被匿名调用，或者你开始按量计费。
- **不知道会怎样**：一个脚本把你的付费接口刷穿，账单和被封的账号一起来。
- **怎么查**：搜 `API 限流 最小方案` · [MDN: 429 Too Many Requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/429)
- **关联**：成本告警 / 预算上限、WAF / DDoS

### 成本告警 / 预算上限
- **是什么**：云厂商的预算与告警：花到某个数就发邮件或短信，有的还能直接停服务。它是唯一能在你睡着时保护你的东西。
- **什么时候会遇到**：第一次用按量计费的服务（函数、带宽、AI API、数据库）。
- **不知道会怎样**：一觉醒来几百刀，而且没有止损开关，只能眼看着它跑。
- **怎么查**：搜 `云 预算告警 设置` · [AWS Budgets](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html)
- **关联**：限流 / 防刷 / 验证码、密钥泄露 / secret scanning

### 备份 / 回滚
- **是什么**：数据有副本、版本能退回。关键是"能恢复到某个时间点"的能力，而不是"我有一份拷贝"。
- **什么时候会遇到**：上线后第一次改数据结构、第一次误删。
- **不知道会怎样**：改坏了没有退路，只能熬夜重建，而用户数据已经没了。
- **怎么查**：搜 `数据库 自动备份 免费方案` · [PostgreSQL: 备份](https://www.postgresql.org/docs/current/backup.html)
- **关联**：错误监控（Sentry 类）、删除权 / 数据保留期

### 错误监控（Sentry 类）
- **是什么**：把线上异常（堆栈、请求、用户）自动收集起来，而不是等用户来告诉你"打不开"。
- **什么时候会遇到**：第一次上线、第一次收到"白屏"反馈。
- **不知道会怎样**：你没有任何线索，只能靠猜，和让用户截图。
- **怎么查**：搜 `Sentry 免费额度` · [Sentry 文档](https://docs.sentry.io/)
- **关联**：备份 / 回滚、日志

### WAF / DDoS
- **是什么**：在流量到达你的服务器之前拦掉攻击流量。Cloudflare 免费版就能挡掉大部分常见扫描和小规模洪水。
- **什么时候会遇到**：小站也会被扫描器扫；被扫就挂的时候。
- **不知道会怎样**：站点被打挂，你还以为是自己代码的 bug。
- **怎么查**：搜 `Cloudflare 免费 WAF` · [Cloudflare: 什么是 DDoS](https://www.cloudflare.com/learning/ddos/what-is-a-ddos-attack/)
- **关联**：限流 / 防刷 / 验证码、CDN 强缓存

## 几个真会咬人的组合

单个词只是词汇。真正出事的是**两点之间**：你在第 3 组学到的「会话录屏」，会在第 5 组变成 GDPR 的雷。下面这几条线，是这份表里最容易真咬到人的：

- **会话录屏 → GDPR / COPPA**：录屏会录到用户输入，也录到小孩。你只是「想看看用户怎么操作」，实际上已经开始处理个人数据了。
- **UTM → 埋点 → 漏斗**：没有 UTM，你知道有人转化，但永远不知道是哪条渠道带来的。
- **.env → secret scanning → 成本告警**：密钥泄露不是「泄露」那一刻出事，是账单爆炸那一刻出事，中间往往差几周。
- **支付通道 → 风控冻结 → Chargeback**：收款顺利时不觉得，一旦冻结或拒付率超阈值，通道直接关，钱和生意一起停。
- **订阅 → churn → 留存**：做订阅的人不看 churn，就永远读不懂自己任何一份数据。
- **平台独家条款 → 分发渠道**：签的时候只有一个平台，等想上第二个才发现签的是排他。

## 怎么补

只收「真撞过」的词，不收「听说过很厉害」的概念。每条五个字段：**是什么 / 什么时候会遇到 / 不知道会怎样 / 怎么查 / 关联**。

一条能进来的标准：如果一个人不知道这个词，他会不会**永远想不起来去搜它**？会，才是扫盲；不会，那是教程内容，不进这个表。
